# compile_defects_nested_call_in_tuple_arg_addition

Programs that compiled and ran wrong before 2026-11-18 (same Makefile shape as
`compile_defects_nested_print_in_call_arg_addition`).

The defect: a call nested inside a tuple or record literal that is itself an argument overwrote
the arguments already evaluated into X0-X7. `fn go(n: int64) -> int64 { show(n, (:tag,
concat("a", "b"))) }` printed an address instead of 42 (silica-999908), and
console_stdin_carrier's `cast_owner(o, (:link_up, concat("stdin:", info)))` cast to the string.

Root cause, in every emitter's `terms/term_user_call_helpers.silica` and its two users:
- A tuple argument is never staged in parallel (`simple_gpr_arg_tree_can_stage` refuses tuple
  types), and neither is any argument tree holding a float. Such a call goes down the sequential
  path.
- There, the only protection for registers already holding arguments is the staged-argument guard
  of `emit_rest_args` and the two-argument reorder in `term_emit_kind_call_tail`.
- Both ask `term_subterm_has_user_call`, which answers true only for user calls (SIR kind 4/5)
  and `list_cons`. Prims that call a helper through the argument registers were invisible, at any
  depth. Examples: `string_concat` (operands in X0/X1), substring, the string predicates,
  `length_bytes`, the transport and actor prims, and string compares.

The fix adds `term_subterm_may_clobber_arg_regs`, which treats every prim as a clobber unless it
is known to stay in the scratch registers. The guard and the reorder now use it. The reorder also
keeps X1, arg2's value, across an arg1 that may clobber.

- `call_in_tuple_after_scalar`: these cases all print the scalar and the tuple's fields; exit 0.
  - two arguments, including inside a let body;
  - three arguments;
  - a call as the first argument;
  - `length_bytes` in place of concat.
- `call_in_record_arg`: a record argument with a float64 field (sequential path), one without
  (staged path), and the three-argument form. Exit 0.
- `call_nested_two_deep`: a tuple in a tuple, a record in a tuple, a tuple in a record. Exit 0.
- `actor_ref_before_tuple_cast`: the carrier's shape through a user wrapper of `cast` and through
  `cast` itself. The sink ends the program with status 0 when both messages arrive intact.

The `.ascomp` goldens are generated by the first good build. Move these into their topic suites
once every host's goldens agree.
